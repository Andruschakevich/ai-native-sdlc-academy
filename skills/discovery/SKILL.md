# Product & System Discovery

1. Read approved Business Intent and repository instructions.
2. Work read-only. Do not modify source or configuration.
3. Map services, modules, data stores, APIs, events and external dependencies.
4. Trace behavior through code, tests, schemas and runtime documentation.
5. Identify source-of-truth ownership, state transitions, side effects and operational constraints.
6. Separate observed fact, inference and unknown; attach evidence and confidence.
7. Produce system-context.md, domain-model.md and impact-analysis.md.
8. Ask domain owners about business meaning; do not infer it from code alone.
9. Independently review critical findings.
10. Return READY_FOR_SPECIFICATION or BLOCKED with unresolved questions.
