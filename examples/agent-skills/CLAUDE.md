# Project Instructions (Illustrative)

This is a fictional training repository. Adapt these instructions to your project and verify compatibility with your installed Claude Code version.

## Project principles
- Follow the approved specification; do not invent business rules.
- Prefer small, focused changes.
- Explain assumptions and unresolved questions.
- Do not add dependencies without justification.
- Never use real customer data or secrets in examples.

## Before changing code
1. Read the relevant feature specification.
2. Inspect existing patterns and tests.
3. Summarize the planned changes.
4. Identify risks and files likely to change.

## Verification
- Run the relevant unit and integration tests.
- Run lint and type checks where available.
- Report commands executed and their outcomes.
- Do not claim a check passed unless it was actually run.

## Review and safety
- Do not modify CI, deployment, access-control, or production configuration without explicit approval.
- Do not perform production actions.
- Keep changes within the agreed scope.
- Escalate ambiguity instead of guessing.

## Definition of done
- Acceptance criteria are addressed.
- Tests cover expected and negative behavior.
- No known secrets or sensitive data are introduced.
- The final summary lists changed files, checks, risks, and open questions.
