# Command: Prepare a Pull Request

Use this checklist before proposing a pull request.

## Steps
1. Read the approved specification and identify its acceptance criteria.
2. Inspect the complete working diff.
3. Summarize the implementation and list changed files.
4. Report tests and checks actually executed, including failures.
5. Identify security, privacy, compatibility, and operational risks.
6. List unresolved questions and deviations from the specification.
7. Draft a concise pull request description.

## Output template
### Summary
### Specification coverage
### Tests and checks
### Risks
### Open questions
### Rollback considerations

Do not merge, deploy, or claim approval. A human reviewer owns those decisions.
